# 実験：外壁の読み係を Sonnet と Opus で比べる（本部棟 f6、2026-11-17）

同じ定義（`.claude/agents/gaiheki.md`）・同じ 18 枚の目盛りつきの面の画像・同じ禁止事項（棟 JSON と他の係の答えを読まない）で、Opus 5.5 と Sonnet 5.5 に外壁の読み係をさせた。どちらもこの会話の中のサブエージェント（API キーは使っていない）。

| 項目 | Opus 5.5（`gaiheki_f6.json`） | Sonnet 5.5（`gaiheki_f6_sonnet.json`） |
|---|---|---|
| 位置合わせのずれた写真 | 6 枚（+10.6・+10.6・+15.8・+42.4・+2.2・切れ端） | 5 枚（+10.6・+15.9・+42.4・+2.0・切れ端）。**042830256 を「ずれなし」と見落とした** |
| 窓の段の高さ | 5.9–8.8 / 9.9–12.9 / 14.0–16.9 / 18.0–21.0 | 5.9–8.8 / 9.95–12.8 / 14.0–16.9 / 18.0–21.0（差 0.1 m 以内） |
| 列 | 9 間・5.32 m ごと | 最上段の小窓 18 列・2.65 m ごと、2〜4 階は凹み 9 本（同じことを言っている） |
| 材質 | 磁器タイル・ガラス・その他 | 磁器タイル・ガラス・コンクリート・その他 |
| 正面玄関の扉 | 見つけた（s15.0–15.9） | 「未確定」 |
| 時間・トークン | 687 秒・約 17 万 | 256 秒・約 11 万 |

## 042830256 の決着

- メインの Claude が画像を直接見た：垂れ幕 4 本が s7〜15、1 階の車路の抜けが s8〜26 に写っている。基準の 042900775 では垂れ幕が s17.6〜25.8 なので、約 +10.6 m ずれている。
- コードの相関（基準の写真と重ねる）でも、ずれ 0 より +10.6 m の方がわずかに高い（0.123 → 0.162）。
- → Opus が正しい。

## 分かったこと

- 段・列・材質のように「見れば分かる」読みは、Sonnet と Opus でほぼ同じ。
- 一番大事な「くり返す並びの中で、写真の位置合わせのずれを見抜く」判断で、Sonnet は 6 枚中 1 枚を見落とした。見落とすと、ずれた写真の箱が窓の照合に混ざる。
- 本部棟 f4・図書館 f1 は Sonnet だけで読んだので、同じような見落としが残っているかもしれない（未確認）。

## 使い方の案（未実施）

1. Sonnet で一度読む（安い）。
2. Sonnet が「ずれなし」とした写真に、コードで柱の間の整数倍のずれを試し、ずれ 0 より明らかに合うずれがあれば、その写真だけ Opus に見せて決めてもらう。
3. 位置合わせのずれを見抜く判断だけは Opus に任せ、段・列・材質の読みは Sonnet に任せる、という分け方もある。
